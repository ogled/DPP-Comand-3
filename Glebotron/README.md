# Глеботрон

Мессенджер через кубсат по схеме store-and-forward. Веб-пользователи пишут на https://glebotron.cosmos1562.space. Сообщения на терминалы встают в очередь, ЦУП передаёт их на спутник во время пролёта, а терминал получает их на одном из следующих пролётов. Так же, в обратную сторону, идут ответы и подтверждения (ACK).

```
браузер ──HTTPS──> nginx :443 ──> gunicorn 127.0.0.1:5001 (app.py) ── SQLite
ЦУП (Laptop-program) ──HTTPS + токен станции──> /gs/v1/*
   └─ serial ─ радиомодуль ⇄ кубсат ⇄ терминалы
```

Сервер работает только с кадрами **GLB**: это прикладной уровень, формат описан ниже. Упаковку кадров в CCSDS или в HMAC-команду спутника делает ЦУП.

## Что где

| Файл | Что внутри |
|---|---|
| `app.py` | Flask: веб-API `/api/*`, API для ЦУП `/gs/v1/*`, команды админа |
| `codec.py` | формат GLB v1: кадры сообщений и ACK, нарезка текста по границам символов UTF-8 |
| `db.py` | схема SQLite, миграции, счётчики `seq` и `radio_id` |
| `quotas.py` | лимиты при открытой регистрации |
| `frontend/` | интерфейс на React и Vite, собирается в `static/` |
| `tools/fake_gs.py` | имитация ЦУП и пролёта: проверка без железа |
| `deploy/` | systemd, nginx, `install.sh` (сервер) и `deploy.ps1` (Windows) |

## Запуск на своём компьютере

```
pip install -r requirements-dev.txt
python -m pytest
python app.py
```

Интерфейс откроется на http://127.0.0.1:5001. База создаётся в `glebotron.db` рядом с кодом.

Чтобы проверить путь через спутник без железа, создайте станцию и прогоните имитацию пролёта:

```
flask --app app add-station test
python tools/fake_gs.py --token <токен> pass --ack
python tools/fake_gs.py --token <токен> send --from 7 --to <ваш номер> --text "Привет с поля"
python tools/fake_gs.py --token <токен> replay
```

- `add-station` печатает токен один раз.
- `pass --ack` проводит сообщение по цепочке «в очереди → ЦУП → спутник → доставлено».
- `send` присылает ответ от терминала #7.
- `replay` повторяет последние кадры: сервер должен отбросить их как дубликаты.

Интерфейс в режиме разработки (сервер `python app.py` должен быть запущен):

```
cd frontend
npm install
npm run dev
npm run build
```

`npm run dev` открывает интерфейс на http://localhost:5173. `npm run build` пересобирает `../static`; сделайте это перед коммитом и деплоем.

## Деплой на сервер

Сервер — `ubuntu@cosmos1562.space`. Там уже работают сайт на :5000 и Xray на :2083, Глеботрон их не трогает. Код лежит в `/opt/glebotron`, база в `/var/lib/glebotron`, настройки в `/etc/glebotron/glebotron.env`.

**Первый раз**

1. С Windows, из папки `Glebotron`, запустите `powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1`. Скрипт прогонит тесты, соберёт интерфейс, скопирует архив и выполнит `install.sh`. Пока сертификата нет, nginx ставится только с HTTP.
2. На сервере выпустите сертификат: `sudo certbot certonly --nginx -d glebotron.cosmos1562.space --deploy-hook "systemctl reload nginx"`.
3. На сервере ещё раз запустите установку: `sudo bash /opt/glebotron/app/deploy/install.sh`. Теперь встанет конфиг nginx с HTTPS.
4. Зарегистрируйтесь на сайте, затем выполните `sudo glebotron create-admin <ник>` и `sudo glebotron add-station cup`. Токен станции нужен ЦУП.

**Обновление:** снова запустите `deploy\deploy.ps1`. Перед обновлением скрипт делает бэкап базы. Если новый релиз не запустился, он возвращает прежний.

**Откат вручную:**

```
ls /opt/glebotron/releases
sudo ln -sfn /opt/glebotron/releases/<релиз> /opt/glebotron/app && sudo systemctl restart glebotron
```

**Проверка:**

```
systemctl status glebotron
journalctl -u glebotron -n 50
curl -s https://glebotron.cosmos1562.space/api/status
```

## Команды админа

На сервере: `sudo glebotron <команда>`. Локально: `flask --app app <команда>`.

| Команда | Что делает |
|---|---|
| `create-admin НИК` | сделать зарегистрированного пользователя админом |
| `ban НИК` / `unban НИК` | блокировка: выход со всех устройств, очередь пользователя снимается |
| `add-station ИМЯ` | новая станция (ЦУП); печатает токен один раз |
| `remove-station ИМЯ`, `list-stations` | отозвать токен станции; список станций |
| `list-terminals`, `name-terminal ID "Подпись"` | терминалы, выходившие в эфир; подпись для справочника |
| `queue` | что ждёт спутника |
| `backup [--dir ПАПКА] [--keep 7]` | копия базы без остановки; на сервере таймер делает её каждую ночь |

## Адреса

| Адрес | Кто |
|---|---|
| 1–999 | **терминалы**. ID прошивается в устройство. Сервер узнаёт терминал по первому кадру от него, заводить вручную не нужно |
| 1000–65000 | **веб-пользователи**. Номер выдаётся случайно при регистрации |

Писать можно на любой ID терминала, даже если он ещё не выходил в эфир. Кадр из эфира с отправителем вне 1–999 сервер отбрасывает: из радио нельзя писать от имени веб-пользователя.

Выданные ID терминалов (ID должен быть уникальным, `Packet.deviceId` сейчас `uint8_t`, то есть 1–255):

| ID | Терминал | Кто прошил |
|---|---|---|
| 2 | Earth (STM32 + SX1268) | — |

## Радиоформат GLB v1

Все поля little-endian. Кадр не больше `GLEBOTRON_FRAME_MAX` байт (по умолчанию 39, это payload HMAC-команды из `StratosatSys/COMMANDS.md`).

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 1 | kind: `0x01` MSG, `0x02` ACK |
| 1 | 2 | msg_id, назначает отправитель |
| 3 | 2 | src |
| 5 | 2 | dst |
| 7 | 1 | `index<<4 \| (count-1)`, до 16 фрагментов |
| 8 | N | кусок текста UTF-8 (в ACK пусто) |

Пример: пользователь #48213 пишет терминалу #7 «Привет», msg_id 517:
`01 05 02 55 BC 07 00 00 D0 9F D1 80 D0 B8 D0 B2 D0 B5 D1 82`.
ACK от терминала: `02 05 02 07 00 55 BC 00`.

Текст режется по границам символов, поэтому каждый фрагмент можно декодировать отдельно. Сообщение не длиннее 160 байт (около 80 кириллических символов). Повтор кадра с другого пролёта сервер узнаёт по паре `(src, msg_id)` в течение 7 дней. Канал любительский, поэтому шифрования нет.

## API для ЦУП

Все запросы — POST с JSON и заголовком `Authorization: Bearer <токен станции>`.

| Путь | Тело | Ответ |
|---|---|---|
| `/gs/v1/uplink` | `{limit, max_frames}` | `{lease_until, items: [{message_id, radio_id, src, dst, frames: ["01 05 …"]}]}`: сообщения выдаются по кругу между отправителями, выдача действует 30 минут |
| `/gs/v1/uplink/result` | `{results: [{message_id, ok, error?}]}` | при `ok` статус «на спутнике», иначе сообщение возвращается в очередь; после 5 неудач — «не удалось» |
| `/gs/v1/downlink` | `{frames: [{hex}]}`, до 200 кадров | `{accepted, duplicates, new_terminals, errors}` |
| `/gs/v1/heartbeat` | `{event: "ping" \| "aos" \| "los"}` | начало и конец сеанса показываются в интерфейсе |

## Ещё не решено с командой железа

- Какой APID отдать мессенджеру на downlink и какой ID команды на uplink. Подтвердить 39 байт на кадр.
- Кто шлёт ACK: терминал (так сделано сейчас) или спутник при приёме.
- Сколько кадров спутник хранит между пролётами. От этого зависят `GLEBOTRON_QUEUE_MAX` и `max_frames`.
