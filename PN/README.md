# ПН: полезная нагрузка Глеботрона

ESP32-S3-CAM с LoRa-модулем E32 на тех же выводах, что и у терминалов (`espS3`): RX 1, TX 2, AUX 14, M0 и M1 на земле.

Нагрузка слушает общий радиоканал терминалов и сохраняет каждое адресованное сообщение: терминалу или человеку на сайте. Сообщения «всем рядом» она не хранит. Весь кэш она без остановки сбрасывает в эфир, пока над ней не окажется терминал.

- Терминал показывает из сброса только сообщения, адресованные ему.
- Терминал, который на связи с сайтом, передаёт на сайт все строки сброса. Если он принял сброс целиком, он отвечает `RESET CACHE <id>`, и нагрузка удаляет всё до этого номера. Строки, пришедшие во время сброса, остаются до следующего.
- Терминал без интернета кэш не трогает: он только показывает своё.

## Протокол

Одна строка — одно сообщение, в конце `\n`. Формат описан в начале `src/main.cpp`; в `espS3` он же лежит в `src/satproto.h`.

```
MSG|<от>|<кому>|<текст>            сообщение: от "7" или "@позывной", кому "*", "3", "@позывной" или "#48213"
SAT|BEGIN|<first>|<last>|<count>   начало сброса
SAT|<id>|MSG|...                   одна сохранённая строка, как была услышана
SAT|END|<last>                     конец сброса, нагрузка слушает
RESET CACHE <last>                 ответ терминала: удалить id <= last
```

Радиоканал полудуплексный: пока идёт сброс, нагрузка ничего не слышит. Поэтому после каждого сброса она слушает 4 с, и ещё 1,5 с после каждой услышанной строки. В это окно терминалы отвечают со случайной задержкой 0,2–1,5 с:

- `RESET CACHE`, если сброс принят целиком и есть связь с сайтом;
- до трёх своих адресованных сообщений, которые ещё не вернулись в сбросе. Терминал повторяет их в каждом окне, пока не увидит их в сбросе (до 30 раз, не дольше 48 часов).

## Камера: /cam

На борту камера GOOUUU ESP32-S3-CAM, настроенная как в скетче CAMERAesp32 (те же выводы и поправки для OV3660/OV5640). Терминал по команде `/cam` просит снимок; запрос повторяется в каждом окне прослушивания, пока нагрузка не ответит (не дольше получаса).

```
CMD|<терминал>|cam                          снять фото для терминала
IMG|<n>|BEGIN|<терминал>|<частей>|<байт>|<ш>x<в>
IMG|<n>|<номер>|<crc>|<base64, до 30 байт>  части 0..частей-1
IMG|<n>|END                                 нагрузка слушает
CMD|<терминал>|again|<n>|31-90,95           терминал просит недостающие части (диапазоны, в один пакет)
```

Снимок 240×176, JPEG; качество снижается, пока файл не уложится в 4 КБ (не больше 137 строк). E32 передаёт не больше 58 байт за один радиопакет, поэтому каждая строка снимка укладывается в один пакет (не длиннее 57 байт): она либо приходит целиком, либо не приходит вовсе. CRC-8 в каждой строке отсеивает испорченные части, и терминал запрашивает их заново. Терминал запрашивает недостающие части после `IMG|…|END`, в каждом окне прослушивания после `SAT|END` и каждые 10 с, если строки снимка перестали приходить. Он сдаётся после 12 запросов подряд, которые не принесли ни одной новой части. Пока идёт снимок, сброс кэша прерывается и начинается заново после него. Показывает снимок только терминал, который его просил; он хранит три последних.

## Кэш

До 300 строк и 48 КБ во флеше (LittleFS), переживает перезагрузку. Одинаковые строки хранятся один раз. При переполнении удаляются самые старые. Номера строк только растут, в том числе после сброса и перезагрузки: по ним терминал отличает новую строку от уже показанной.

## Сборка

```
pio run -e esp32s3cam -t upload       # N16R8 (OPI PSRAM)
pio run -e esp32s3_n8r2 -t upload     # N8R2
pio device monitor                    # журнал: что сохранено, какие сбросы подтверждены
```
